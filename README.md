# 寻宝朝元 · V4 认知走查

当前剧情以“剧情与交互精修补丁 V3.0”为准，对白样式以文末“全局剧情对白框统一优化”为准；此前实现与验收记录保留作为历史说明。

现有四幕项目的逻辑补丁：**任务走查 → 记录认知断点 → 汇总设计机会**。四幕始终使用 V1 初始服务，设计迭代与再次评估留到后续阶段。

## 运行

无构建步骤、无外部依赖。直接打开 index.html，或在项目目录运行：

```sh
python3 -m http.server 8000
```

访问 http://localhost:8000。建议 16:9 桌面浏览器，右上角可全屏。Tab、Enter、空格与右方向键可操作；放大弹窗支持 Escape 关闭并返回原焦点。

## 四幕与报告

1. **参加活动**：第一幕原剧情、主动发现摊位和主动询问保持。四问成功，记录成功后继续走查。
2. **认识目标**：保留远景、手持卡照片和 V1 卡片。Q1 ✓、Q2 ⚠、Q3 ⚠、Q4 ✓。扫描后回到原版卡片，显示“唉，光看这张卡还是有点摸不着头脑……”与“算了，先进去看看吧。”，继续寻宝。
3. **寻找目标**：保留四张暗场照片与原数字牌，不增加文字特征。Q1 ✓、Q2 ⚠、Q3 ✓、Q4 ✓。扫描后仍在困惑场景，继续原版贴签。第三幕 Q4 只说明操作进度可见，不说明匹配正确。
4. **核验完成**：在三清殿后侧提交 V1 卡片，依次模拟核验、盖章、展示完成纪念。三句新收尾同时表达完成的开心与识别理解的困难。四问成功，进入报告。

报告从实际记录读取四个节点，生成 **4 个任务节点 / 2 个成功节点 / 2 个问题节点 / 2 类设计机会**。报告后通过“查看设计机会”进入独立的两类方向展示页，注明尚未实施、尚待再次评估；可返回报告或重新体验。两页保留 16:9 下的文字阅读空间。重新体验清空评估、贴签、核验、盖章和报告状态，从序幕开始。
